课程规划与生成模块开发设计

2026-10-03 · Python 后端 · 固定地图 1.0.1-model-reviewed · 设计 v1

本文是开发设计。地图读取、校验和快照导出代码已经整理；课程规划、供应商调用、异步任务、语音生成与发布服务尚未实现。SQL未执行到任何数据库。

沿用已确认的总体结构：调度 → 教学任务 → 生成课程与音频 → 质检与保存。下述8个子模块是内部开发分工，不替换总体图。

初版：Python + FastAPI + 独立异步Worker + PostgreSQL任务队列和业务存储 + 音频对象存储。地图通过只读仓库访问，模型与语音通过可替换接口调用。

结构化设计 · JSON Schema · 接口示例 · 数据库草案 · Python接口

输入、输出与边界

输入：固定版本的TargetDefinition、LearnerProfile、需求与预算。输出：有审核状态的LessonPackage。内部负责目标和资源选择、生成、质检与发布；能力掌握更新由模块2执行，实时角色状态和公开负载投影由会话服务执行。

目标调度

实现：rules

  • 证据不足先选低负担诊断；尚未检查不等于不会
  • 优先当前交流阻碍和到期保持检查
  • 选择需求相关缺口，检查理解、互动修复的长期遗漏
  • 建议前置可跳过，不推导整个等级掌握
  • 记录选择理由、证据ID和其他候选

资源选择

实现：rules_with_optional_model_review

  • 按词义ID而非单词字符串排除已掌握资源
  • 认识但提取失败的表达进入练习，不重新解释整遍
  • GL、SSGL为成人默认候选；YL需明确开启
  • GSE未分级和星号状态保留，不自动给课程定级
  • 候选词必须与实际任务相关，主题命中不等于教学适配
  • 必要新资源必须在测评前确认理解，或记录支持，不据此误判沟通能力

教学任务构建

实现：rules

  • 用户、地图和能力摘要版本
  • 一个主目标与单独记录的附加目标
  • 明确的学习目的与理由
  • 主题、输入和支持条件
  • 已知、新学及复习资源
  • 学习、应用及独立变体要求
  • 目标必要意义和允许改述
  • 任务模式与音频证据要求

文本与任务生成

实现：LLM

  • 先检查是否有版本及条件兼容的审核模板
  • 无匹配模板时模型按结构化合同生成
  • 中文意图→英文说法→必要解释→个人替换→遮答案表达→信息差应用
  • 具体化双方可见事实、角色私有信息、回应规则、关键意义和可接受结果
  • 独立变体改变影响结果的条件，不只换名字
  • 生成pass/partial/fail/unjudgeable锚点，但锚点不是已校准评分器

格式或内容失败可限次修订；没有合格模板则标needs_review，不伪造回退资源

文本与任务质检

实现：rules_and_LLM

  • Schema、固定版本和目标引用
  • 逻辑限制与可行结果
  • 输入资源已学或支持被明确记录
  • 阶段、输入条件与允许帮助
  • 角色不替用户完成关键动作
  • 独立变体不暴露示例答案
  • 评分检查只评价主目标必要意义
  • 用户拒绝、个人立场或不熟悉专业知识不算语言失败
  • 客户端负载不含对方私有信息和评分锚点

音频生成与复用

实现：speech_service_and_rules

  • 为已审核文本生成或匹配适配音频
  • 学习示例和测评输入分别标用途
  • 异步执行，固定声音配置和文本版本
  • 网络失败按阶段重试，不重做已完成文本

音频质检

实现：speech_tools_and_rules

  • 资产存在且能解码播放
  • 关键词、数字、否定与文本一致
  • 语速、长度与清晰度符合任务条件
  • 测评字幕和提示显示规则
  • 语音转写对照是辅助检查，不是绝对正确性证明

failed_audio_qa，修订音频；有文本不能宣称听力课程已可使用

课程保存与交付

实现：rules

  • 仅必要文本和音频检查通过才能learner_ready
  • 课程版本发布后不可原位改写，修订生成新版本
  • 保留模型、提示、地图、规则、资源和音频版本
  • 服务端保留全部角色和评分内容；由会话服务按阶段投影公开负载
  • 未通过的草稿可保存研究，但不得成为用户可见课程

异步状态与失败恢复

queued → planning → generating_text → checking_text → generating_audio → checking_audio → approved → needs_review → failed → cancelled

  • 阶段进度和课程版本分开保存
  • 重试可恢复成功阶段，记录尝试次数、错误分类和预算
  • 生成请求固定profile_version，用户变化不修改执行中的任务；完成时按明确新鲜度政策交付或重规划
  • idempotency_key仅在同一用户范围去重，同key不同请求体返回冲突
  • 取消和worker回收使用job版本/lease，过期worker不能覆盖新结果
  • 模型超时、拒绝、限流、格式错误、内容错误和音频错误分别处理
  • 发布课程与完成事件在同一事务保存，消费者按事件ID去重

API合同

方法路径输入输出与边界
POST/v1/course-generation-jobs目标可选、profile_version、需求、预算；目标未给则调度选择202 GenerationJob；认证用户由服务端确定；需Idempotency-Key
GET/v1/course-generation-jobs/{job_id}GenerationJob阶段、错误摘要和公开结果引用；不返回私有草稿
POST/v1/course-generation-jobs/{job_id}/cancel取消请求及当前状态；幂等
GET/v1/lessons/{lesson_id}/versions/{version}服务端内部LessonPackage；学习者端不得调用此完整包接口
POST/internal/v1/lessons/{lesson_id}/publish全部门槛通过的固定版本；仅内部流程允许

数据库与事件

保存learning_plans、teaching_assignments、generation_jobs、lesson_versions、quality_reports、audio_assets和outbox_events。公开课程版本不可原位改写；用户数据与角色私有负载分开授权读取。模型输出不能自行设置发布通过。

已有20节课程如何接入

将research/course-qa-2026-10-02的20节课程作为任务合同与错误注入回归样例。它们含学习步骤、角色规则和独立变体，但没有真实声音，也未调用生产生成器，须显式字段适配，不能整包发给App。

  • main_objective_id → target_ids中的主目标
  • learning → learning_materials与学习步骤
  • supported_practice → 有提示练习任务
  • independent_task、role_response_rules、assessment → 独立任务合同及私有角色规则
  • release、audio_assets → QA与资产状态，不继承为上线许可

开发顺序与验收

M1 合同、调度规则及任务队列骨架

  • 同输入和规则版本可重现调度
  • 已知资源不重复解释
  • 一次课程一个主目标
  • 失败和不确定证据可触发诊断
  • 幂等及重启恢复

M2 文本生成与QA

  • 真实供应商结构化输出
  • 20节样例字段映射
  • 注入错误及正确改述回归
  • 未通过不能发布
  • 缺少模板正确进入needs_review

M3 音频链路与课程发布

  • 实际声音与文本核查
  • 公开/伙伴/评分负载隔离
  • 版本不可覆盖
  • 重试不重复计费阶段或重复发布

M4 与能力模块及会话模块联调

  • 真实用户摘要读入
  • 会话实际支持记录可评价
  • 真实延迟及成本基线
  • 保持与迁移试点；不预先承诺最快

仍需确定

  • 大模型、语音供应商及调用预算
  • 用户单次时长与新资源负荷，作为可配置初始参数
  • 真实评价和学习效果校准由相邻模块及试点提供
