# 反馈 5—7：提示、评价与录音发送

## 已确认的原因

- 独立应用原先必须手动结束；对方已经接受安排后，界面仍停留在对话中。
- 失败记录的主因是模型返回的评价格式不合法。系统拒绝更新能力是正确的，但界面把系统错误概括成“证据不足”，并把最后一句识别文本当成完成依据。
- 独立检查会按任务政策隐藏对方字幕。原来的中文占位句只是界面提示，并非对方实际说的话。
- 上传、识别与回复完成前，客户端没有对话气泡，只在底部显示等待状态。

## 修复

1. 提示改为紧凑的分级列表：意图、句型、示例、所学表达；在对应条目下展开内容，并显示加载及错误。
2. 隐藏字幕的气泡明确显示“对方语音”；结果页按有效评价引用展示回应，系统错误不归因于学习能力。
3. 评价器携带完整 JSON Schema，结构不合法时修复一次；仍不合法返回可重试的服务错误。不会降低证据检查要求。
4. 对方提出对话结束后，后端检查全部关键条件、可信度及实际学习者引用，通过才结束独立任务。保留手动结束入口。
5. 松开录音后立即创建自己的气泡。上传和识别状态、识别文本、等待回应与失败重试均在原气泡更新。
6. 新增 `InputProgress` 公共合同及 `GET /v1/sessions/{id}/inputs/{input_id}`；原始识别元数据与请求摘要留在服务端。输入重试沿用相同标识，避免重复转写和能力证据。

设计参考：[Apple 状态反馈](https://developer.apple.com/design/human-interface-guidelines/feedback)、[进度指示](https://developer.apple.com/design/human-interface-guidelines/progress-indicators)、[底部面板](https://developer.apple.com/design/human-interface-guidelines/sheets)。采用操作位置附近的状态反馈与可展开面板。

## 验证范围

后端 74 个测试与 4 个子测试通过。新版模型评价器对原失败记录做只读检查，返回合法结构、完整关键检查和有效引用，判断任务已完成；没有改写用户历史记录。

手机界面测试使用隔离数据库与受控识别响应，模拟回复延迟，确认气泡能及时出现；模拟结果不计入用户能力。完整结果见 `verification/feedback-5-7-2026-10-04.json`。
