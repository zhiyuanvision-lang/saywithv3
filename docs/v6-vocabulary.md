# 全局查词与生词本

## 页面与操作

沿用旧版 iOS 的查词卡片和日期分组生词本；学习、引导、独立、复习、提示、示范、反馈及生词详情中的英文词均可点击。可编辑输入框保留正常的文字编辑操作。

```text
英文句子：Are you available tomorrow?
                 ↓ 点击 available
┌─────────────────────────────┐
│ available                ×  │
│ 英 /音标/ 🔊   美 /音标/ 🔊  │
│ adj. 可用的；有空的          │
│ ─────────────────────────── │
│ ＋ 加入生词本／✓ 已在生词本  │
└─────────────────────────────┘
```

浮动卡片靠近所点的词，可关闭或点外部关闭；内容较长时卡片内滚动。查词时暂停课程音频，录音保留供回听或重录。释义加载失败可重试；保存失败保留卡片，不显示保存成功。

```text
我的 → 生词本
┌ 今天 ─────────────── 2 个 ┐
│ available /音标/     🔊  › │
│ adj. 有空的；可用的       │
│ careful /音标/       🔊  › │
│ adj. 小心的               │
└───────────────────────────┘
点词条 → 生词详情
┌ 生词 ────────────── 移出 ┐
│ available                 │
│ 英美音标与发音            │
│ 词义 → 搭配 → 例句＋翻译  │
│ 收藏时的原句              │
└───────────────────────────┘
```

词头、词形和释义复用 `../SayWith` 的词典解析服务；核心资料固定为 `dictionary_core_with_scenarios.jsonl`，在本项目保留同源副本作为服务不可用时的后备。不同词形按解析得到的词头收藏，同账号去重，账号之间隔离。当前生词本属于新版学习账号，未自动迁移旧版账号的数据。

## 对能力记录的影响

| 行为 | 保存内容 | 对能力与课程的影响 |
|---|---|---|
| 查词 | 词头、原词形、原句、时间、关联会话与目标 | 弱线索；不判定“不会”，不降低目标状态 |
| 收藏 | 用户主动选择练习该词，理解与提取仍为待检查 | 收藏词及语境进入教学任务；适合当前沟通任务时优先复用 |
| 独立任务中查词 | 在任务表现中保存“查词释义”支持 | 本次完成可保留，但不增加无帮助独立完成证据 |
| 移出生词本 | 停止以收藏为由优先安排 | 保留过去查词、学习和能力证据 |

例如收藏 `available` 后，记录是“用户想练这个词，是否理解和能否提取待确认”，不是“不会邀请朋友”。课程可在商量时间的任务中安排 `Are you available tomorrow?`。只有经过有效评价的具体表现，才能判断是词义理解、听辨还是提取存在缺口。收藏接口不生成这些强判定；用词评价与生词先尝试入口负责收集具体证据。

## 反馈导出

在项目根目录运行 `make feedback`，反馈文本写入 `support.md`，截图保存到 `tmp/feedback-inbox/<工单ID>/`；再次运行会去重。文件保留在本地，不纳入 Git。可将 `support.md` 和其中图片的绝对路径作为 agent 的输入。

默认导出保留工单状态；`make feedback-close` 在成功保存后关闭已导出的工单。后台单次最多返回 500 条，达到上限会提示，可使用脚本的 `--id` 指定工单。

## 生词与课程闭环（2026-10-03）

```text
学习：当前沟通任务
┌ 生词先试一试 ──────────────────┐
│ 告诉 Alex 你明天下午有空。      │
│ [按住试说] [看词义]             │
│ 提示递进：词义 → 句式 → 示例    │
│ [稍后练，继续课程]              │
└───────────────────────────────┘
           ↓ 实际尝试或稍后练
原有学习 → 引导练习 → 独立应用
           ↓ 有效用词证据
生词详情：当前词义表现＋下次检查时间
```

- 每课最多选择 2 个生词；来源目标关联优先，再检查任务文本与词义语境。模型质检确认词义、表达自然及任务相关性，不相关内容不能发布。没有匹配词时正常推进主课程。选词内容多次未通过质检时，保存失败报告与延后原因，保留待练习状态，生成原沟通目标的课程。
- 先尝试阶段隐藏学习示例、完整示范与答案入口；词义、句式、示例按需提供。查词及实际提示在服务端记录，不能由客户端声称“无帮助”。可跳过，不自动判为失败。
- 生词尝试和正式对话分别记录词义、原句、录音、识别、实际帮助、课程/地图版本和模型/规则版本。有效评价须引用真实学习者回应，引用内容要包含对应词或已登记词形；低可信度、不可用录音、测试内容和未使用词均不新增用词能力判定。
- 当前词义独立使用一次记录 provisional；跨会话重复使用可记录 demonstrated；间隔至少 7 天后再次独立使用才记录保持。隔期检查使用 1、3、7、14、30 天的初始调度规则，需后续真实用户数据校准。未使用、改述、跟读及收藏本身均不能证明不会或已掌握。
- 到期词可进入对应沟通任务的复习推荐。自动主路径最多每 5 次规划插入 1 次由到期生词驱动的目标选择，用户主动选择复习不受此限制。移出生词本后停止优先选词，过去证据仍保存。

后端合同：`NotebookEntry`、`LexicalSelection`、`LexicalPractice`、`LexicalPracticeInput`、`LexicalPracticeAttempt`、`LexicalResourceState`、`LexicalResult`；正式任务通过 `TaskAttempt.lexical_resources`、`AssessmentResult.lexical_results` 关联。版本为兼容扩展 `1.0`，调度规则 `lexical-v1`。完整 Schema 位于 `backend/contracts.schema.json`，示例已合入 `research/system-dataflow-2026-10-02/contracts.examples.json`。

接口：`POST /v1/sessions/{id}/vocabulary-attempts`，支持录音尝试、提示和稍后练。生产口语尝试必须提供本人录音；文字提交仅用于 fixture 界面测试。相同输入 ID 重试复用结果，不重复累计证据。
